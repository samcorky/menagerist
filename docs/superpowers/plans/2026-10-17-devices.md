# Devices and Admin Area Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let people see and sign out their own devices, let administrators see and sign out anyone's, and move administrator screens under `/admin/`.

**Architecture:** A device is the existing identity `Session`. It gains `user_agent`, `client_ip`, `client_platform` and `client_mobile`, captured once at session creation from a small `ClientDevice` value read from request headers. Five use cases (three own-device, two permission-gated administrator) and five routes sit on four new `SessionRepository` methods. The frontend derives labels with `bowser` and Client Hints, adds a devices section to the account page, and gains an `/admin/` area holding the moved users page and a new devices page.

**Tech Stack:** Python 3.14, FastAPI, SQLAlchemy 2 async + Postgres, Alembic, pytest; SvelteKit 2 / Svelte 5 runes, TypeScript strict, shadcn-svelte, Vitest, Playwright, `bowser` (MIT).

**Spec:** `docs/superpowers/specs/2026-10-17-devices-design.md`. Header diagnostics (its section 4.7) is a separate first slice and is assumed done; this plan does not depend on it.

## Global Constraints

- Python 3.14+; `poe typecheck-backend` (`mypy --strict`) must pass. TypeScript strict (`poe typecheck-frontend`).
- Dependency direction `entrypoints → adapters → application → domain`. `identity` imports no other module.
- Every port ships an in-memory twin; application and router tests use it. Only real-adapter tests are `@pytest.mark.integration`.
- Coverage floors: domain 100%, application 100%, shared_kernel 100%, adapters 80%.
- British English in code, comments and copy. Comments short, only where intent is unclear. Google-style docstrings.
- The only new dependency is `bowser` (MIT, frontend). **Do not add `ua-parser-js`** (2.x is AGPL, incompatible with Apache 2.0). Check `.github/renovate.json` and bundle size first.
- UI copy says "devices", never "sessions", "nodes", "edges" or "graph".
- Internal hrefs use `resolve()` from `$app/paths`. API calls go through `src/lib/api/client.ts`; never edit `src/lib/api/generated/`.
- Every `.svelte` or `.svelte.ts` file is written by the `svelte-file-editor` subagent.
- **Never run `git add` or `git commit`.** Each task ends at a checkpoint where the user may commit.
- Responses expose the session row id only. Never a token, token hash, or the raw `Cookie` header.

## Review Focus

Failure modes a straight reading would miss. Each is pinned by a test in the task named.

1. **Foreign and unknown ids look the same** (Tasks 3, 4, 5). A member revoking another person's device gets 404, identical to an unknown id, never 403.
2. **Revoking the current device** (Tasks 3, 4). Refused with 409 by id comparison, for members and administrators, so nobody locks themselves out through this route.
3. **"Active" matches the sign-in rule** (Task 3). A device idle past `MENAGERIST_SESSION_IDLE_HOURS`, or expired, is not listed, and one that `GetCurrentUser` would reject is never shown as live.
4. **No secrets in responses, reprs or logs** (Tasks 2, 5). The token, its hash, cookies and `user_agent` never reach a log line or a `repr`; `SessionResponse` has no token field.
5. **Admin list and per-user filter share one query** (Task 4). `user_id` for an unknown user returns an empty list, not 404.
6. **The `/admin/` move leaves no stale references** (Task 7). A repo grep for `settings/users` comes back empty.

## Task 8: Device label helper

**Files:** `frontend/package.json`, `src/lib/devices.ts`, `tests/devices.test.ts`. `.ts` helper may be written directly; any `.svelte.ts` goes through the subagent.

- [ ] Add `bowser`; check Renovate grouping and the production bundle size (import only what `Bowser.parse` needs).
- [ ] `describeDevice({ userAgent, platform, mobile })` returns `{ label, kind }`. Label: browser from `bowser`; system from `platform` when present, otherwise from `bowser`; `mobile === true` with no system gives "{browser} on a phone"; no usable data gives "Unknown device". Plus a relative-time helper unless one already exists.
- [ ] `kind` is one of `tool | phone | tablet | desktop | unknown`, chosen in this order: `tool` when the user agent names a command-line client (`curl`, `python-requests`); `phone` when `mobile` is true, or the user agent says iPhone, or Android with a `Mobile` token; `tablet` when the user agent says iPad, or the platform is Android with `mobile` false and no `Mobile` token; `desktop` for Windows, macOS, Linux or ChromeOS; otherwise `unknown`.
- [ ] Tests from the spec table: Firefox on Linux, Chrome on Windows (with and without hints), Edge, Safari on macOS and iPhone, Chrome on Android, Samsung Internet, curl, `null`, empty and junk strings. Add the two real captures: Windows desktop (`?0`, `"Windows"`, `Chrome/155`) gives "Chrome on Windows" / `desktop`; reduced Android UA (`Android 10; K`, `?1`, `"Android"`) gives "Chrome on Android" / `phone`. Assert a `kind` for every row.
- [ ] `device-icon.svelte` (via `svelte-file-editor`): `tool` to `Terminal`, `phone` to `Smartphone`, `tablet` to `Tablet`, `desktop` to `Monitor`, `unknown` to the question-mark circle (confirm the name in the installed Lucide version). Icon is `aria-hidden`; the text label carries the meaning. Known limits: laptop and desktop share one icon, and iPadOS Safari reports as a Mac.
- [ ] Run the frontend checks. **Checkpoint.**
