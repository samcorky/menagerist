73. Field-row editing UI, across the schema editor, "Add field" (WI-18 revised) and the attributes editor: a full interaction-pattern pass is needed for the growing set of per-row actions (pin/highlight, replace, save-for-reuse, remove, and now "Make this a field on `<item type>`" and overlay remove). Currently every action is a permanently-visible icon button, which is getting crowded on the field row. Options to weigh: keep all icons always visible (current, most discoverable, least tidy); reveal on row hover/focus (common desktop pattern, but needs a touch-friendly fallback per the design guidelines' general hover-reveal precedent for bulk-select checkboxes, §14); collapse into a context/overflow menu (fewer icons, one more click, easier to add future actions without more crowding); or a drag handle for reordering (WI-13, stretch, currently unimplemented — WI-23's column reordering uses up/down buttons instead of drag, which is the only precedent in the app so far). Needs a decision that stays consistent with how the rest of the app already handles row actions elsewhere (e.g. connection rows, list items) before picking one pattern for field rows specifically. Default: not yet decided; current icon-row style stands until reviewed.
